# Codex Lane Demo Expanded Prompt

## Title + Style Block

Title: "Multiple Instructions. Concurrent Codex Work. No Collisions."

Visual identity: technical editorial, high-trust, precise. Background `#171513`, foreground `#F4EFE4`, muted paper panels `#EDE3D1`, ink `#26211B`, amber accent `#E0A23B`, red conflict `#D4513C`, green safe `#5F9F73`, blue Product `#5A7FA8`. Typography uses `Newsreader` for display moments and `IBM Plex Sans` / `IBM Plex Mono` for UI, labels, and command lines.

## Rhythm Declaration

Pattern: before-friction -> collision -> PRODUCT-PROMPT -> concurrent-build -> sequencing -> resolved-CTA.

The video should feel like a crisp product explainer for developers. It starts with visible mess, then narrows into a reliable operating loop. The peak is the "Product receives four instructions at once" moment, followed by a satisfying mechanical lock/claim sequence.

## Global Rules

- Keep fake screenshots legible and believable: sidebar threads, chat bubbles, file locks, status rows, handoff cards.
- Show motion as coordination, not spectacle: lines connect, locks close, conflict is blocked, Product sequences.
- Use persistent visual motifs: four lane colors, repo-state board, lock icons, thread cards.
- Every scene includes 2-5 background decoratives: grain, grid, ghost labels, status ticks, orbital linework.
- No real app screenshots are required; fake UI panels are acceptable and should look intentional.

## Scene Beats

1. **Before: one bloated thread**
   - Concept: One conversation tries to hold design, tech, business, and product context at once. The thread becomes visually crowded and ambiguous.
   - Choreography: chat cards stack and jitter; file badges collide; red conflict indicators appear.

2. **Manual parallelism without awareness**
   - Concept: Separate threads exist, but they cannot see each other. Two lanes reach for the same file.
   - Choreography: Design and Tech panels slide in from opposite sides; their file paths overlap; a red "same file" warning stamps across the middle.

3. **After: Product receives multiple lane instructions**
   - Concept: The user gives four lane instructions at once in Product/Captain. Product becomes the router and integrator.
   - Choreography: a central Product prompt expands, then splits into four lane tickets.

4. **Concurrent work with claims**
   - Concept: Codex runs safe pieces concurrently while every lane checks status and claims files. Non-overlapping lanes proceed; overlaps are blocked.
   - Choreography: status command types on; file locks click shut; green and amber lines move in parallel.

5. **Product sequences conflicts**
   - Concept: The Product lane does not let conflicts merge blindly. It orders shared-file work and links handoffs.
   - Choreography: Product drags two tasks into order; one conflict becomes a sequenced pair; handoff cards appear.

6. **Final takeaway**
   - Concept: The promise resolves into one clear statement: multiple instructions can run concurrently without the user babysitting collisions.
   - Choreography: the four lanes orbit the repo board, locks settle, final line holds.

## Negative Prompt

Avoid generic neon AI dashboards, default purple gradients, unreadable code walls, tiny text, and claims that Codex magically shares chat memory. Be explicit that shared repo state is the awareness layer.
