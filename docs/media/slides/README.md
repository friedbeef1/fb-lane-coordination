# Flow Builder — presentation

**[Open the presentation (PDF, 19 slides)](flow-builder-introduction.pdf)**

Deep discussions in separate workstreams are valuable. The difficult part is
connecting their conclusions: what should run first, what can run together,
what remains blocked, and what a new stakeholder priority displaces.

This walkthrough shows how Flow Builder (FB), a Codex plugin, helps make those
decisions visible without replacing the product or program manager's judgment.

## Inside the deck

- Concrete coordination problems and matching FB responses.
- Six ongoing workstream conversations feeding Product/BFM (Build For Me).
- A real queue preview: after `$bfm`, before implementation.
- Priority and stakeholder trade-offs, with an illustrative example.
- Installation, everyday use, and the separate **Push Live** boundary.
- GitHub and [James's LinkedIn](https://www.linkedin.com/in/jamesyeang) for questions and collaboration.

## Evidence boundaries

The queue screenshot is a real example, not proof that its listed tasks were
completed. Other illustrations and the priority-change example explain the
workflow. They are not measured time savings, guarantees of conflict-free
delivery, or claims that native Codex cannot coordinate work.

The PDF is a presentation, not a narrated video. Technical plugin identifiers
remain `fb-lane-coordination@fb-lane`; the public name is Flow Builder.
